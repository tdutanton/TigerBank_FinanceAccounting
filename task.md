КОНТЕКСТ
ТигрБанк не останавливается в развитии своих сервисов и планирует улучшить программную архитектуру
ранее написанного модуля «Учет финансов». Заказчик просит вас доработать доменную модель так, чтобы
она была реализована с соблюдением принципов SOLID и ключевыми идеями GRASP

ПОСТАНОВКА ЗАДАЧИ
Данная задача является продолжением предыдущей «Домашнее задание №2. Конструирование программного
обеспечения»

Требования
На встрече с командой пришли к выводу, что будут уместны следующие паттерны:

Фабричный метод: позволит изолировать логику инициализации объектов
Фасад: поможет объединить по смыслу несколько методов. Например, можно упаковать в отдельный фасад
всю работу с Category (создание, изменение, получение, удаление). Также стоит реализовать отдельные
фасады для BankAccount, Operation. Всю работу с аналитикой тоже можно вынести в отдельный паттерн
данного типа
Команда: каждый пользовательский сценарий можно представить в виде паттерна Команда
Шаблонный метод: пригодится для импорта данных из файлов различных форматов. В сценарии загрузки из
файла отличается только часть парсинга данных (из json / yaml / csv), а оставшаяся часть, отвечающая
непосредственно за обработку данных, будет одинаковой
При этом функциональные требования остались без изменений:

Расчет финансов:
Работа с доменной моделью: создание, редактирование и удаление счетов, категорий, операций (
доходов/расходов)
Аналитика:
Подсчет разницы доходов и расходов за выбранный период
Группировка доходов и расходов по категориям
Любая другая аналитика
Импорт и экспорт данных:
Экспорт всех данных в файлы: CSV, YAML, JSON
Импорт данных из файлов: CSV, YAML, JSON
Управление данными:
Возможность пересчета баланса в случае выявленного несоответствия (предусмотреть процедуры
автоматического или ручного пересчета)
Статистика:
Измерение времени работы отдельных пользовательских сценариев
Ключевая задача
Необходимо разработать классы доменной модели модуля «Учет финансов» с соблюдением принципов SOLID,
с обязательным использованием DI-контейнера, ключевыми идеями GRASP: High Cohesion и Low Coupling, а
также рядом паттернов GoF

Результатом выполнения является консольное приложение, в котором продемонстрирована функциональность
разработанной доменной модели

Основная цель задания – подстроить архитектуру под использование конкретных паттернов

Формат оценивания

Формат скринкаста: видео до 3 минут, с пояснительными комментариями в режиме реального времени. На
видео объясните:

почему выбранные решения работают
как они интегрируются в архитектуру
как они связаны с требованиями задачи
В качестве репозитория можете выбрать любой. Обязательно проверьте наличие публичного доступа (можно
протестировать в режиме инкогнито)

Будут проверяться только материалы по ссылкам (одной или двум). Не используйте гиперссылки (
отправляйте ссылку без сокращений). Прикрепленное внутри LMS видео проверяться не будет
